# Changelog

## 1.0.0 - first public release
* The number of genomes per job in the multi-genome tools (genome screen, DefenseFinder, PADLOC, GenoVi, RRE-Finder) is the setting `MAX_GENOMES_PER_JOB` (default 20).
* All versions are pinned to the ones the released version was built and tested with: every package in the conda environment files (`conda_environments/`, `tools/*/install/`) is an exact version, the container images (miniforge3, nginx) are pinned by digest and redis by tag, the git checkouts by commit. `webserver/locks/<env>.txt` lists everything that is installed in each environment (name, version, build). New builds therefore give the same tools as the tested ones.
* E-mail messages are editable in the admin (E-mail messages): subject and text of "job finished", "job failed" and "results will be deleted soon", with placeholders; the page starts with the default texts (a migration creates them), *Restore the default texts* resets them. A test address on that page (or `manage.py test_email --to ...`) sends a sample of each. Local mode used the Django defaults for sender and subject prefix (`[Django]`, root@localhost); now `SENDER_EMAIL` and `[BacLab]` in every mode.
* The project is called **BacLab** everywhere (the command `./baclab`, `baclab-client`, `baclab-fetch`, `BACLAB_*` settings, the Compose project name). An installation made under the old name keeps working: `.labmate` is renamed `.baclab` on first use; to keep using its existing Docker volumes set `COMPOSE_PROJECT_NAME=labmate` in `.env` before updating (a new project name means new, empty volumes).
* New tools from the HIPS deployment: PADLOC, DefenseFinder, GToTree, GenoVi, BiG-SCAPE, BiG-SLiCE, GATOR-GC, RRE-Finder, PanBGC,
  BASALT (off by default, needs 128 GB RAM). Each lives in its own folder `webserver/tools/<name>/` (`tool.py`, script, conda environment,
  page, optional database installer); pages, menus, FAQ and URLs are generated from it.
* Add tools without programming: admin -> *Custom tools* (script + optional conda environment + result view). Environments are kept on the data volume.
* Tool switches in the admin; `enabled_tools.csv` is now only the shipped default.
* `./baclab` command: `install`, `update` (backup, pull, rebuild, migrate, database check), `db status|install`, `selftest`, `backup`, `restore`, `status`, `logs`.
* Database catalog (`baclab/db_catalog.py`) with installers that run in a maintenance container (`dbtools`) so production can keep `/databases` read-only.
  Tools whose database is missing say so on their page instead of failing. Admin page *System status*; `manage.py check_databases` / `selftest`.
* AMRFinderPlus and MOB-suite databases moved out of the image into `databases/` so they survive updates.
* Production setup works on a fresh machine: settings generated by the installer (no secrets in git), HTTP by default and HTTPS when certificates are present,
  worker size taken from the machine, e-mail and allowed hosts configurable, upload limit 20 GB.
* Fixes: nightly clean-up task crashed on a wrong field name and never removed result archives; tools' post-processing ran twice per job; failed
  post-processing now fails the job; the e-mail address of the user is no longer written into the result archive.
* Optional user accounts: login, "my jobs" (own runs, naming, longer retention) and user groups whose members see each other's runs. Everything still works without an account; `ACCOUNTS_ENABLED` / `ALLOW_SIGNUP` settings.
* Notification e-mail: users can store an address in their account; administrators can restrict allowed domains with regular expressions (admin -> E-mail policy, or `NOTIFICATION_EMAIL_DOMAINS`).
* Lab features: key findings per run, projects, run again, use results in another tool, private runs, NCBI accession input, methods text and tool versions,
  Genome screen pipeline, JSON API + `baclab-client`, job limits, fast/heavy queues with a light worker, disk/queue monitoring, usage report, stuck-job and disk alerts
  (e-mail + chat webhook), result-deletion warnings, optional LDAP login (needs `INSTALL_LDAP=1`).
* Admin live monitor: CPU (per core), memory, GPU (utilisation, memory, temperature), storage and running jobs, refreshed every 2 seconds.
* The tools menu is one panel with a column per category and alphabetically sorted tools. Administrator guide in `docs/ADMIN_GUIDE.md`; quick tips on the admin start page.
* Found and fixed by a clean-room build and test of everything (see below): installing on rootless Podman and on network file systems (NFS/Lustre: no `:z` volume labels,
  ports 8080/8443), SELinux sharing between the web and worker containers, update really recreating the containers under podman-compose (and backing up first), the worker
  being able to build admin databases (writable `/databases` where needed, readable database files), RRE-Finder's missing `RRE_short` files, a results-page crash while an
  admin task ran, missing example data (phylogeny, taxonomy), Genome Mining without any database (clear notice instead of a failing job), the annotation results page.
* Every tool is now a folder: the first-generation tools (BLAST, cblaster, Abricate, MLST, SPAdes, Genome Mining, the annotation pipeline, ...) moved from
  hand-wired views, URLs, forms and classes into `webserver/tools/<name>/` (`tool.py`, page, results page, guide card, script, citation), like the newer ones.
  Their menus, guide pages and home page are generated from the tool definitions; custom databases are built by the tool they belong to; the
  cblaster failures (no hits, ValueError) use the shared `JobError`. New `Tool` options: `file_only`, `requires_databases`, `exclude`, `settings_key`,
  `custom_database`.
* Real example data for the tools (a *K. pneumoniae* isolate with plasmids for typing/resistance/plasmid tools, *B. subtilis* for GECCO, four *C. trachomatis* genomes for Panaroo and Gubbins, 12 type-strain 16S genes for the phylogeny, real QC reports for MultiQC); provenance in `webserver/baclab/example_data/README.md`.
* Every tool page offers "Download Example Data" and "View Example Results" (a default of the shared page template); BiG-SCAPE, BiG-SLiCE and GenoVi got real example data, and the BLAST and Genome Mining examples pick a database the installation has. Only BASALT (128 GB RAM, off by default) has none.
* Better examples: Taxonomy Finder (12 type-strain 16S genes, 16S mode; its 16S script no longer crashes on hits that belong to several taxa) and Genome Mining (a Sfp query against a database of two Bacillus genomes, built once from `example_genomes.zip`). The static demonstrations now carry the plots, PDFs and viewers (BiG-SCAPE with its database) of the results pages. The table page selector follows the theme colours.
* Documentation for Read the Docs (`docs/`, `.readthedocs.yaml`) with a Demonstrations page with three static demonstrations: the clickable site, the site as a logged-in lab member (my jobs, group runs, key findings, methods, projects, API keys) and the administration pages (users and groups, job records, usage, system status, live-monitor snapshot, ...).
* `manage.py prerun_examples` prepares the example results of all tools at once. Table cells without a value are empty instead of "NaN".
* Platform citation: placeholder for the BacLab paper (`CITATION.cff`, `baclab/citations.py`).
