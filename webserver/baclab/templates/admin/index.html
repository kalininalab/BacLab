Quick tips (full guide: docs/ADMIN_GUIDE.md in the BacLab folder)

On the server (in the BacLab folder): ./baclab update new version, data is kept and a database backup is made · ./baclab status · ./baclab logs -f django · ./baclab backup · ./baclab restart after editing webserver/.envs/.production/.django.

A tool says its database is missing? ./baclab db status shows what is missing, ./baclab db install installs it (./baclab db install padloc gtdbtk for chosen ones). Downloads can be large.

Hide or show a tool: Tool switches — add a row with the tool key (e.g. padloc) and untick enabled. BASALT is off by default (needs 128 GB RAM).

Add a tool without programming: Custom tools → Add. Write a bash script (it gets $INPUT_DIR, $OUTPUT_DIR, $CORES_PER_JOB, $PARAM_<NAME>), optionally a conda environment, save, run Build the conda environment from the list, then tick enabled. Scripts run on the server — only trusted administrators should have this permission.

User accounts (optional): add users under Users and put them in a group via User groups — group members see each other's runs on the "my jobs" page. Nobody needs an account to use the tools. Switch accounts off with ACCOUNTS_ENABLED=False, allow self-registration with ALLOW_SIGNUP=True.

Limit notification e-mail addresses: E-mail policy — one regular expression per line for the part after the @ (e.g. example\.org or .*\.edu). Empty = any address.

Edit the e-mails users get: E-mail messages — subject and text of the "job finished", "job failed" and "results will be deleted" messages, with placeholders such as {job_id}; leave a text empty for the default. Type an address under Send a test to and save to receive a sample of each message (local mode: it appears in the server log).

Fair use and monitoring: Job limits cap simultaneous jobs per user/group; Live monitor shows CPU, memory, GPU and storage in real time; System status shows disks, workers and queues; Usage gives hours per user/group/tool. Stuck jobs and full disks are e-mailed to you (and to chat with NOTIFY_WEBHOOK_URL).

A job is stuck: Job records → select → Mark selected as failed. Error details are in the job's Errors section.

Users' e-mail, results kept for 30 days, cores per job: webserver/.envs/.production/.django.
